# Automated News Report Generator

Pipeline that scrapes RTVE's live news, summarizes the most relevant articles in Spanish with a local LLM, and builds a daily PDF report. Portfolio project: not a commercial product, no monetization planned.

**[README en español](README_ES.md)**

## Live demo

**[alex-server.taile13699.ts.net](https://alex-server.taile13699.ts.net/)** — a real, interactive dashboard: pick how many news, a time window (hours or days), and optionally a category, then click the button and it runs the actual pipeline (scraping + local LLM summary) and shows the resulting PDF. Not a cached/precomputed demo.

Self-hosted on the author's own hardware (not a cloud platform), so it's only reachable while that machine is on (roughly 9:00-23:00 CET). See [Deployment](#deployment) for why. Deployment code lives in a separate repo: [Automated-News-Report-Spaces](https://github.com/AlejandroBeldaFernandez/Automated-News-Report-Spaces).

## What this does

1. Downloads RTVE's Google News sitemap with a self-identifying User-Agent.
2. Parses it and keeps only news from a configurable recent time window.
3. Scrapes each article's full body, short description and topic category with Playwright.
4. Stores everything in SQLite, idempotently.
5. Selects the most recent general-news articles, optionally filtered by category.
6. Summarizes each one in Spanish with a local LLM (`Qwen/Qwen2.5-1.5B-Instruct`, CPU, no external API).
7. Builds a PDF: title, category, AI summary, and a citation (source + link) for each article, built in code from the database, never generated by the model.

## Source: RTVE

All content comes from **RTVE (Radiotelevisión Española)**, the Spanish public broadcaster. All rights belong to RTVE. For verified, complete information, always refer to RTVE directly (rtve.es); this project produces short automated summaries, not a substitute for the original reporting.

## Why the sitemap, not RSS or plain scraping

The original plan was RTVE's classic RSS feed via `feedparser`. Checking RTVE's actual `robots.txt` showed that feed redirects to a host (`api2.rtve.es`) that is both stale (dated 2022) and blocked by its own `robots.txt`. This project uses RTVE's **Google News sitemap** instead (`rtve.es/sitemaps/sitemaps-news.xml`), explicitly allowed in `robots.txt` (`Allow: /sitemaps/*.xml$`), live, and linking directly to each article. A custom User-Agent is used for the sitemap download, since RTVE's `robots.txt` blocks the Python default (`Python-urllib`); Playwright, used for scraping article pages, keeps its normal browser User-Agent instead, since RTVE sits behind an Akamai bot-management layer that is more likely to flag an atypical UA on human-facing pages.

## Legal note

`robots.txt` only grants technical crawling permission, not usage rights over the content. RTVE's legal notice prohibits reproducing its content without authorization, a standard clause across Spanish media, not specific to RTVE. This project's mitigation: the full scraped article text is stored only for internal use (to generate the summary) and is **never** shown or published, in the notebook, the PDF, or the dashboard. What's public is only the title, category, an AI-generated summary, and a link back to the original RTVE article.

## Pipeline and automation

- Orchestrated with **Prefect** (independent tasks with retries; `Url` as the SQLite primary key makes retries idempotent, no duplicate rows).
- Containerized with **Docker**.
- Runs in **GitHub Actions**, triggered manually only (`workflow_dispatch`), not on a daily schedule. How a daily cron *would* be set up is documented (commented out) in the workflow file, but intentionally not enabled — this project isn't meant to run unattended every day.
- The image is pushed to DockerHub as part of the same workflow.

## Deployment

The original plan was Hugging Face Spaces. In practice, the account used for this project could not create any Space with compute (Docker, Gradio+CPU, or ZeroGPU all blocked; only static Spaces were allowed), for reasons that couldn't be diagnosed (email verified, no notice from HF, no immediate support channel on the free plan). Alternatives were checked concretely, not assumed: Streamlit Community Cloud's free tier (1GB RAM) is too small for the ~2.9GB model; Google Colab with a `share=True` tunnel works but isn't always-on; Oracle Cloud's Always Free tier is viable but requires a credit card and manual VM administration.

The dashboard is self-hosted instead, on the author's own machine (Ryzen 7 6800H, 32GB RAM, already running Docker), exposed publicly via **Tailscale Funnel** (free, no credit card, no port-forwarding on the home router). See the [Automated-News-Report-Spaces](https://github.com/AlejandroBeldaFernandez/Automated-News-Report-Spaces) repo for that code.

## Known limitations

- `.artBody` (the scraped article container) also includes "related articles" boxes mixed into the paragraph text; not filtered out yet.
- The live demo is only reachable while the host machine is on, not 24/7.
- Summaries occasionally exceed the requested word limit; it's a prompt instruction, not a hard constraint.
